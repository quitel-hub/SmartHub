
**SmartHub** — це повнофункціональна інтелектуальна екосистема для автоматичного аналізу, OCR-розпізнавання та перекладу навчальних конспектів, лекцій і білетів. 

Проєкт поєднує в собі асинхронного Telegram-бота на базі **aiogram 3**, аналітичний веб-дашборд на **React 19** та хмарну базу даних **Supabase (PostgreSQL)**, працюючи як єдиний синхронізований Full-stack комплекс.

---

## 🏛️ Архітектура та Технологічний Стек

Проєкт побудовано за модульним принципом із чітким розділенням відповідальності (Separation of Concerns) та застосуванням сучасних патернів проєктування:

### Backend (Python 3.12)
* **Асинхронний двигун:** `aiohttp` (веб-сервер, роздача статики та обслуговування REST API ендпоінтів).
* **Telegram-бот:** `aiogram 3` (асинхронна взаємодія за допомогою механізму Long Polling).
* **Модуль OCR:** `pytesseract` + бінарний рушій *Tesseract OCR* (підтримка змішаного розпізнавання `ukr+eng`).
* **Багатопотоковість:** `concurrent.futures.ThreadPoolExecutor` (винесення важких синхронних OCR-обчислень в окремий пул потоків для захисту головного асинхронного циклу `event loop`).
* **Автоматичний переклад:** `deep-translator` (двосторонній асинхронний переклад конспектів).

### Frontend (React 19)
* **Стек:** `React 19` + `TypeScript` + `Vite 8` + `Tailwind CSS` + `Lucide React` (іконки).
* **Двомовні вкладки:** Інтерактивний перегляд автентичного оцифрованого тексту та його англомовної версії з лінивим завантаженням (Lazy Loading) через бекенд-інтерфейс.

### База даних та Хмара
* **СКБД:** Хмарна реляційна база даних **PostgreSQL** на платформі **Supabase**.
* **Деплой:** Автоматизована контейнеризація за допомогою **Docker (Multi-stage build)** на сервері **Render**.
* **Режим 24/7:** Інтеграція із зовнішнім кроном **cron-job.org** для самопінгування веб-сервера та запобігання «засинанню» контейнера.

## 🛠️ Застосовані патерни проєктування

1. **Singleton (Одинак):** Реалізовано у класі `DatabaseAdapter` для забезпечення єдиної точки підключення до бази даних та запобігання витоку ресурсів.
2. **Adapter (Адаптер):** Використовується для роботи з клієнтом Supabase та інтеграції з Google Sheets API.
3. **State (Стан):** Застосовано через кінцеві автомати (FSM) в aiogram для контролю життєвого циклу користувача та залізобетонного блокування спаму фотографіями під час OCR-обробки.
4. **Observer (Оглядач):** Механізм `DocumentEventManager` асинхронно сповіщає підписників (Telegram-інтерфейс, Google Sheets, Supabase логер) про успішне завершення розпізнавання.
5. **Builder (Будівельник):** Клас `ReportBuilder` інкапсулює покрокове формування фінального структурованого звіту (Header, Content, Metadata, Footer).
6. **Factory Method (Фабричний метод):** Клас `ProcessorFactory` динамічно створює об'єкти процесорів залежно від типу документа (звичайний текст чи математичні формули).
